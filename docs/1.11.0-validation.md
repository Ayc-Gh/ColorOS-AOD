# 1.11.0 · Android 17 适配与运行状态

本版沿用 1.10.1 的长期签名，可覆盖同签名 1.10.1；旧签名 1.10.0 仍需按之前的迁移说明安装。versionCode 35，Android 13+，arm64-v8a。

## 修复与改进

- 运行亮度入口兼容 `int` 与 Android 17 的归一化 `float` 参数。浮点分支保持小数精度、使用 0–1 上限，并保留 NaN、负值等系统特殊值。初始亮度通过本机 `BrightnessSynchronizer` 的真实转换函数匹配，避免被再次乘倍率。
- 仅注册一条有效的运行亮度链路，避免 fallback 与主入口嵌套时重复乘倍率；没有适用入口时明确报告不可用。
- 按本机可用类注册单击回调；缺失的旧全景入口作为版本差异跳过。保留现有双击门限与独立双击处理，不将“注册成功”描述成实体手势已经验证。
- 每项功能统计实际注册、首次命中、失败与可跳过入口，消除内部捕获异常后外层仍输出 success 的问题。部分注册失败显示部分可用。
- 新增主页入口“功能运行状态”：区分配置同步、已加载、已触发、未知，以及当前加载的版本；未回复的后台进程保持未知，不能据此判断功能失败。
- 状态只在打开页面或手动刷新时查询，关闭页面后取消回调与接收器；没有周期采样、文件日志或刷新率强制写入。跨进程消息使用随机请求标记并限定目标包名；Android 14+ 直接验证发送方 UID，避免依赖远端缓存的请求标记；Android 13 使用私有请求标记并仅短暂重试一次。
- 浅色和深色主题分别设置状态栏、导航栏图标对比度。
- 明确标注“面板实际刷新率尚未可靠测得”，不将系统 60Hz 模式或内容提交帧率当成面板扫描频率。

## 验证

- 2026-11-10，OPPO Find X7 Ultra / PHY110，Android 17 / `PHY110_17.0.0.100(CN01)`，LSPosed API 102。
- 单元测试覆盖亮度精度、特殊值、边界、旧／新接口继承关系与功能状态；正式版 lint 无错误；R8 与资源压缩 Release 构建通过。
- 同签名覆盖升级成功，配置保留；系统界面实际注册 `DozeService.setDozeScreenBrightness(float)` 并命中。
- 稳定环境下系统原亮度读数 1870，1.6 倍为 2992，1.3 倍为 2431；系统默认旁路恢复 1870。数值是厂商内部亮度刻度，不是 nits。
- 系统界面与系统息屏设置均回复已加载 1.11.0；加载与首次命中分开显示。后台息屏设置未回复时显示未知，不会沿用过期成功状态。
- 30 秒、1 分钟分别在 30.034 秒、60.013 秒触发结束（截止事件时间，非毫秒级视觉测量）；10/30/60 分钟、4 小时低光、实体黑屏单双击和其他机型未扩大验证范围。

未重新测量修复倍率后的纯电池功耗；升级前的功耗样本是在倍率失效的旧版取得，不能直接作为新版功耗结论。未获得面板真实 1Hz/60Hz 扫描的可靠证据。
